# Известные ловушки

- Git на цій машині має core.autocrlf=true. Без .gitattributes (eol=lf) SKILL.md отримують CRLF і tests/pack падає на `startsWith('---\n')`. Не прибирати .gitattributes.
- uv встановлено через winget, Python 3.12 — через `uv python install`; у нових терміналах uv є в PATH, у старій сесії треба перезапустити shell.
- Git Bash (інструмент Bash агентів) не бачить uv у PATH. Викликати повним шляхом: `/c/Users/Ihor/AppData/Local/Microsoft/WinGet/Packages/astral-sh.uv_Microsoft.Winget.Source_8wekyb3d8bbwe/uv.exe`. У PowerShell — оновити `$env:Path` з Machine+User.
- TypeScript 7.x несумісний з typescript-eslint 8.72 (peer <6.1.0) — не оновлювати TS без перевірки (ADR 011).
- jsdom закріплено на 29.1.1: jsdom 30+/31 вимагає Node ^24.15, а на машині Node 24.12.0. Оновлювати разом із Node.
- Starlette 1.x TestClient вимагає `httpx2`; зі звичайним `httpx` падає StarletteDeprecationWarning (у pytest filterwarnings=error). Див. ADR 015.
- `python` у Git Bash — це аліас WindowsApps (Python 3.14), який зависає в очікуванні stdin. Використовувати `uv run …` або `.venv/Scripts/python.exe`.
- У тестах із `from __future__ import annotations` модель тіла запиту FastAPI оголошувати на рівні модуля: локальний клас FastAPI мовчки сприймає як query-параметр.
- Конфіг ruff/mypy/pytest лежить у кореневому pyproject.toml; гейти запускати з кореня репозиторію. Ruff RUF001–003 вимкнені свідомо (кирилиця в повідомленнях).
- PyInstaller-бандл sidecar (apps/backend/packaging) містить файли міграцій як data і hidden imports alembic.context/op/ddl.sqlite, sqlalchemy.dialects.sqlite.pysqlite; smoke перевіряє POST /v1/projects і `alembic_version` у БД (2026-11-14). `Hidden import "tzdata" not found` нешкідливий: zoneinfo тягнуть alembic/pydantic, але clipforge не використовує named zones; якщо з'явиться ZoneInfo — додати tzdata. Dev-залежність hypothesis потрапляє в бандл через pydantic.v1 plugin — виключити (`--exclude-module`) у M8.
- Mypy-гейт запускати на весь backend: `uv run mypy --strict apps/backend` (не лише clipforge), інакше помилки в tests/ пропускаються.
- Після `npm ci` бінарник Electron може не завантажитися (немає `node_modules/electron/dist`). Виконати `node node_modules/electron/install.js` (бере zip із кешу `%LOCALAPPDATA%\electron\Cache` або з мережі).
- `.venv\Scripts\python.exe` на Windows — launcher: з'являються два процеси python (launcher і інтерпретатор). `child.kill()` на launcher завершує й дочірній (перевірено) — `taskkill /T` не потрібен.
- Electron main шукає Python відносно `out/main` (лише нерозпакована dev-розкладка). У M8 замінити на PyInstaller-бандл sidecar.
- У test mode `CLIPFORGE_*` env передаються sidecar як є (крім CLIPFORGE_SESSION_TOKEN); у production усі `CLIPFORGE_*` вирізаються з env дочірнього процесу.
- OpenRouter відхиляє будь-який аудіо-запит STT кодом 402, якщо баланс < $0,50 (перевірено live 13.11.2026 для обох STT-моделей; generation_id = null, нічого не списано). Тіло: `{"error":{"code":402,"message":"This request requires at least $0.50 in balance for audio","metadata":{"limit_source":"openrouter_credits","remedy_hint":"…"}}}`. M3: 402 → зупинити run, показати українською потребу поповнити баланс щонайменше до $0,50; не повторювати.
- Текст `IntegrityError` SQLAlchemy містить SQL-параметри (зокрема JSON-значення). API і логи ніколи не віддають `str(exc)`; лише код помилки.
- Читання-потім-запис кліпу — тільки через `Database.write_session()` (`BEGIN IMMEDIATE`). У deferred-транзакції конкурентний коміт дає "database is locked", а не `StaleRevision`.
- JSON-стовпці (`VersionedJson`) не відстежують мутацію на місці: значення присвоювати цілком.
- Майбутні batch-міграції SQLite (перебудова таблиці, напр. FK `clips.analysis_run_id` разом з `analysis_runs`) мають тимчасово вимикати `foreign_keys`, бо він увімкнений на кожному з'єднанні.
- Alembic вантажить міграції з файлів: PyInstaller-бандл має містити `clipforge/storage/migrations/**` як data плюс hidden imports SQLAlchemy/Alembic.
- Швидкий `-ss` перед `-i` на MPEG-TS переходить на keyframe після цілі; pre-seek лише для mov/mp4/matroska (ADR 018).
- У Git Bash `python3` — теж аліас WindowsApps і зависає на stdin; лише `.venv/Scripts/python.exe` або `uv run`.
- Input `-ss` FFmpeg рахує від `start_time` контейнера: не додавати canonical origin до pre-seek, інакше на джерелі з ненульовим початком ціль перескакується (ADR 018, уточнення 2026-11-14).
- `JobRepository.transition` — bulk UPDATE без синхронізації сесії: щоб прочитати job після нього, потрібен `session.refresh(job)`.
- Не чекати завершення команди за шаблоном "passed": ruff друкує "All checks passed!".
- POST /v1/sources/{id}/relink рахує SHA-256 нового файлу синхронно в HTTP-запиті, без cancel і прогресу (контракт docs/04 — синхронний): для 50 ГБ це хвилини, і вони затримують зупинку sidecar. Перенести в job із прогресом — M6 (рев'ю M1, 2026-11-14).
- Якщо файл зник або змінився під час фонового SHA-256, джерело отримує hash_status=failed; relink до нового шляху тоді неможливий (FR-004 вимагає збігу хешу), лише імпорт як нового source. Хеш перераховується на старті, тільки коли файл знову доступний за збереженим шляхом із тим самим size/mtime.
- `tests/test_storage_support.add_source` пише `probe_json`/`canonical_origin`, що не відповідають схемі відповіді API: GET /v1/sources/{id} для такого рядка дає ValidationError. Тести, яким потрібні GET або успішний relink, мають реєструвати джерело через POST /v1/sources.
- Після рестарту sidecar `ExportService.recover()` пише manifest і catalog закритого batch в output dir: перевірки «тека порожня» після recover хибні.
- Не створювати FastAPI-застосунок (`create_app`/`client_for`) у кількох потоках одночасно: FastAPI глушить `UnsupportedFieldAttributeWarning` через `warnings.catch_warnings()`, а він у Python 3.12 не потокобезпечний. Попередження прослизає, і `filterwarnings=error` валить тест (рідкісний flaky у `test_concurrent_patches_…`, 2026-11-14). Клієнтів будувати до пулу потоків, паралелити лише запити.
