# Технічне завдання ClipForge Local

Версія 1.0 від 12 листопада 2026 року. Робоча назва продукту — ClipForge Local.

## 1 Мета та очікуваний результат

Створити персональний застосунок, який допомагає перетворювати довгі локальні ігрові відео на окремі фрагменти для майбутнього монтажу. Основний користувач не має досвіду професійного монтажу. Основні матеріали — стріми та записи GTA, тривалістю від 30 хвилин до 6 годин; коротші файли також підтримуються.

Користувач додає файл, вибирає категорії моментів, запускає транскрипцію та пошук, переглядає пропозиції, коригує межі, підтверджує фрагменти й отримує окремі MP4. Ручне створення фрагментів працює незалежно від AI.

Успіх означає економію часу на відборі, відсутність втрати даних та передбачуваний експорт. Прогнозування переглядів або гарантованої вірусності не є функцією продукту.

## 2 Межі версії

### Обов'язково

- Локальний Windows-застосунок для одного користувача; проєкти, кілька джерел у проєкті, один source на один clip.
- MP4, MKV, MOV, WebM із підтримуваними FFmpeg кодеками. Фактична підтримка визначається probe/decode, а не лише розширенням.
- Вибір аудіодоріжки для транскрипції та окремо для експорту.
- MAI-Transcribe 2 і Gemini 3.5 Transcribe як перемикні STT-адаптери через OpenRouter.
- Імпорт SRT/VTT і нормалізованого JSON із часовими позначками.
- Категорії, додаткові побажання, мовні налаштування, бажана тривалість.
- Окрема конфігурована текстова модель для відбору.
- Прев'ю, синхронізована транскрипція, створення й редагування меж, підтвердження / відхилення.
- Пакетний експорт підтверджених кліпів, manifest JSON, CSV-каталог, необов'язковий SRT для кожного кліпу.
- Відновлення після збою, скасування, контроль повторних запитів та витрат.
- Автоматизовані тести й Windows-пакування.

### Наступні версії

Семантичний аналіз відеоряду/емоцій, пошук тихих візуальних сцен, імпорт відео за URL, автоматична публікація, монтаж кількох кліпів у ролик, вертикальне кадрування, ефекти, озвучення, обкладинки, хмарна синхронізація, команди, live-stream processing. Ці функції не повинні з'являтися як фальшиві активні кнопки.

### Прийняті припущення

Windows 11 x64 — ціль першого релізу, а не вже перевірена характеристика комп'ютера власника. Український інтерфейс; мову джерела визначає провайдер або користувач. Початковий бюджет для live AI задає власник. При відсутності ключа всі локальні функції доступні. Остаточний model ID аналізатора визначається в M0 після capability probe; непідтверджений ID не зашивається в код.

## 3 Ролі та основні сценарії

Єдина роль — власник локального робочого простору. Авторизація обліковим записом не потрібна. Межі між desktop renderer, основним процесом і backend визначаються технічно, а не ролями користувачів.

UC-01: створити проєкт → додати відео → вручну вказати інтервали → експортувати без API.
UC-02: додати відео → вибрати категорії → перевірити орієнтовні витрати → транскрибувати → знайти кандидати → переглянути → підтвердити → експортувати.
UC-03: імпортувати транскрипцію → перевірити відповідність джерелу → шукати моменти без повторного STT.
UC-04: відновити перервану обробку з останніх валідних результатів.
UC-05: змінити категорії → повторно проаналізувати ту саму транскрипцію → зберегти ручні рішення.
UC-06: знайти переміщений оригінал → перевірити його ідентичність → продовжити роботу.

## 4 Функціональні вимоги

Коди FR є стабільними ідентифікаторами. При реалізації кожен FR повинен мати посилання на перевірку в матриці tests. P0 — обов'язковий для релізу; P1 — поліпшення після P0. Нижче всі вимоги P0, якщо прямо не зазначено P1.

### Проєкти та джерела

**FR-001. Проєкти.** Створення, перейменування, відкриття, архівування проєкту. Назва 1–120 символів, пробіли по краях обрізаються. Архівування прибирає зі звичайного списку і зберігає дані.

**FR-002. Імпорт.** Native file picker і drag-and-drop через безпечний Electron bridge; довгі файли реєструються посиланням на локальний шлях без завантаження через браузер і без обов'язкового копіювання оригіналу. Після імпорту показати ім'я, розмір, тривалість, відео й аудіодоріжки.

**FR-003. Перевірка.** FFprobe і коротка decode-перевірка відхиляють пошкоджений/нечитабельний файл, файл без відео або недоступний шлях. Джерело без аудіо дозволяє ручне нарізання; STT недоступний із поясненням.

**FR-004. Ідентичність.** Зберігати canonical path, size, mtime, quick fingerprint і фоновий SHA-256. Quick fingerprint не є доказом ідентичності. Після змін джерела блокувати використання старих таймкодів до перевірки. Relink потребує повного збігу хешу; інший файл імпортується новим source.

**FR-005. Доріжки.** Користувач вибирає один track для STT, а також один track або всі доступні для експорту. Default — track із default disposition, інакше перший. ID — стабільний stream index. Не змішувати доріжки без явної опції.

**FR-006. Збереження.** Автозбереження змін у SQLite, без кнопки загального Save. При помилці запису показати невдалу дію; не вдавати, що дані збережені.

### Пошуковий профіль

**FR-007. Категорії.** П'ять категорій: funny, action, fails, unexpected, game_details. Multi-select має OR-семантику. Default — усі п'ять. Порожній вибір блокує запуск пошуку, а не ручне нарізання.

**FR-008. Усі категорії.** Загальний checkbox підтримує checked/indeterminate/unchecked. Перемикання не запускає AI автоматично. Кнопка запуску створює snapshot налаштувань для analysis run.

**FR-009. Побажання.** Необов'язковий текст до 2000 символів. Передається як низькопріоритетна умова відбору; не може вимагати виконання команд або змінювати JSON-контракт. Відображати введений текст, не вигадувати автоматичні побажання.

**FR-010. Тривалість.** Default бажаного AI-кліпу 15–90 секунд; користувач може налаштувати 5–600 секунд, min ≤ max. Це обмеження AI-добірки. Ручний фрагмент може мати будь-яку валідну тривалість у джерелі, не менше одного доступного кадру.

**FR-011. Ліміт добірки.** Default до 20 кандидатів на source за analysis run; діапазон 1–100. Це максимум, не вимога заповнити квоту. При нестачі відповідних сцен повертати менше або нуль.

**FR-012. Повторний пошук.** Новий analysis run використовує поточний transcript revision; STT не повторюється, якщо аудіо/модель/опції не змінилися. Раніше відхилені й підтверджені кліпи не скидаються.

### Транскрипція

**FR-013. Провайдери.** STT adapter із двома model ID, спільним нормалізованим виходом. Якість не визначати за маркетинговим рейтингом; порівняти на матеріалі власника. Перемикання не запускає витрати без дії користувача.

**FR-014. Час.** Запитувати segment + word timing; MAI — verbatim. Якщо word timing недоступний, дозволений явний segment-level fallback із відповідною позначкою. Не синтезувати нібито точні таймкоди слів із plain text.

**FR-015. Частини.** Default core window 300 с із контекстом 5 с з кожного доступного боку; фактичний upload window ≤310 с. Враховувати limit розміру payload та таймаут. При завеликому запиті ділити core навпіл і перераховувати контекст. Зберігати core та upload межі окремо.

**FR-016. Відповідність оригіналу.** Аудіо для STT походить із вибраного stream, без видалення пауз чи прискорення. Нульова точка відповідає canonical video timeline. Відсутній звук на початку доповнюється тишею відповідної тривалості.

**FR-017. Об'єднання.** Перерахунок chunk-local часу в source milliseconds; відсікання дублів на перекриттях за часом і текстом. Справжні повтори фраз у різні моменти зберігаються. Не об'єднувати speaker IDs різних chunks як встановлену ідентичність.

**FR-018. Покриття.** Для кожного chunk стан: pending/running/succeeded/failed/cancelled/unknown_outcome. Не позначати весь source транскрибованим за наявності неуспішного інтервалу. Частковий аналіз доступний лише за явного вибору й із позначенням пропусків.

**FR-019. Імпорт тексту.** SRT/VTT і normalized JSON приймаються з валідацією формату, часу, порядку, джерела та діапазону. TXT без часу доступний як довідка; не використовується для точного автоматичного нарізання. Для SRT/VTT зберігати timing_level=segment і mapping segment IDs.

**FR-020. Перегляд і виправлення.** Пошук у транскрипції, перехід до репліки. Виправлення тексту зберігає source timestamps, створює revision і позначає пов'язані AI-оцінки застарілими. Ручні межі кліпів не змінюються автоматично.

### Відбір кандидатів

**FR-021. Окремий аналізатор.** Текстова модель отримує search profile, структуровану транскрипцію й сусідній контекст; STT model не виконує цей етап. Model ID/версію prompt/schema зберігати в run.

**FR-022. Докази.** Кожен кандидат містить існуючі first/last word або segment IDs, evidence IDs, категорії, пояснення, оцінки й visual_review_required. Відсутні/переставлені/чужі IDs відхиляються.

**FR-023. Заземлення.** Слова стрімера про екшн є підставою перегляду, але не доказом побаченої події. Текстовий аналіз завжди має evidence_type=transcript. Для action, unexpected та явно візуальних fails — visual_review_required=true.

**FR-024. Межі.** Початкові межі походять із evidence + контекст, default до 3 с до і 4 с після. Не обрізати межі лише для попадання в max, якщо втрачена розв'язка: запропонувати needs_review або пропустити. Остаточні межі затверджує користувач.

**FR-025. Ранжування.** Оцінити зрозумілість, початок, завершеність, емоцію, новизну і відповідність профілю. Показувати пріоритет і пояснення, без відсотка «вірусності» або неправдивої точності.

**FR-026. Дедуплікація.** Близькі інтервали однієї події об'єднувати або групувати, зберігаючи категорії та evidence. Один кліп може мати кілька категорій; не створювати копію для кожної.

**FR-027. Якість контракту.** Модельний JSON проходить schema validation + semantic validation. Одна bounded repair спроба дозволена в межах бюджету; після повторної помилки run=failed, без частково вигаданих результатів.

**FR-028. Різноманітність.** Серед якісних кандидатів застосувати diversity reranking за категоріями/подіями. Не додавати слабкі сцени лише для квоти категорії. Критерій категорії не заміняє загальної якості.

### Перегляд і рішення

**FR-029. Робочий екран.** Список кандидатів, плеєр, шкала часу, межі, транскрипція й пояснення. Прев'ю кліпу не потребує окремого фінального render. Для непідтримуваного player-кодека створювати proxy із правильним timeline mapping.

**FR-030. Ручний кліп.** Доступний із будь-якого source, навіть без аудіо/API/транскрипції. Створюється з поточних In/Out або введених таймкодів; evidence_type=manual.

**FR-031. Редагування.** Поля HH:MM:SS.mmm, кнопки ±1 с, установлення In/Out з плеєра, повернення рекомендованих меж. Межі валідуються до запису. Undo останньої зміни меж у відкритій сесії.

**FR-032. Статуси.** suggested → approved або rejected; обидва можуть повертатися до suggested. Export state є окремим полем, а не заміняє review state. Зміна меж після експорту створює новий revision і позначає попередній експорт застарілим.

**FR-033. Пакетні дії.** Вибрати кліпи для експорту; лише approved дозволені. При пакетному підтвердженні показати кількість і окремо кількість visual_review_required; не трактувати непереглянуту сцену як переглянуту.

**FR-034. Фільтри.** Категорія, source, статус, тривалість, текст; сортування за пріоритетом і часом. Відфільтровані/необрані кліпи не потрапляють у batch без явного вибору.

**FR-035. Порожні та проблемні стани.** Окремі пояснення: немає транскрипції, немає відповідних моментів, API не працює, source переміщений, proxy готується. Для кожного — наступна доступна дія.

### Експорт

**FR-036. Формат.** MP4, H.264, yuv420p, AAC за наявності audio. Без кропу, водяного знака, музики й вшитих субтитрів. Зберігати пропорції, застосовувати лише технічно необхідний even-dimension padding. Default libx264 CRF 18, preset medium; профіль записувати в manifest. Це якісне перекодування, не lossless.

**FR-037. Точність.** Canonical інтервал [start_ms,end_ms). Перший кадр із presentation time ≥start, жодного кадру з PTS≥end. Допуск меж для CFR — один frame interval; для VFR — фактичний локальний frame interval. Аудіо зберігає синхронізацію; тестовий A/V drift ≤50 мс.

**FR-038. Джерело.** Фінальний export бере оригінал, не proxy. Перед стартом перевіряти ідентичність source. Під час export працювати з незмінним clip revision і profile snapshot.

**FR-039. Черга.** Default один FFmpeg render одночасно; обмежений пул STT окремо. Невдача одного clip не скасовує успішні. Batch має partial_failed при змішаному результаті.

**FR-040. Імена.** Безпечний basename: source stem + clip ID + revision + start/end. Очищати Windows reserved names/символи, обмежувати довжину. За колізії додавати suffix, не перезаписувати існуючий файл мовчки.

**FR-041. Атомарність.** Render у temp у цільовій файловій системі; ffprobe і decode check; atomic rename у фінальне ім'я тільки після успіху. Скасований/невалідний результат не показувати готовим.

**FR-042. Каталог.** Export manifest JSON і CSV UTF-8 BOM з роздільником `;`: source_id, clip_id, revision, title, categories, start_ms, end_ms, duration_ms, review_status, path, export_status. Нейтралізувати spreadsheet formula injection у текстових клітинках.

**FR-043. Субтитри.** Опційний SRT зі зміщенням до clip-local zero, trimming по межах, без від'ємного часу. Зберегти повний transcript JSON окремо від SRT. За segment-only timing не заявляти word precision.

**FR-044. Історія.** Показати готові exports, відкрити файл/папку дозволеною native дією. Повторний export того самого snapshot пропонує використати результат або створити новий файл; AI повторно не викликається.

### Надійність, налаштування та витрати

**FR-045. Прогрес.** Показувати етап, завершені/всього chunks або clips, elapsed; відсоток — тільки якщо знаменник відомий. ETA позначати приблизним. Невідомий час провайдера показувати indeterminate.

**FR-046. Скасування.** Cancel блокує нові tasks, завершує власні subprocesses, зберігає готові результати, позначає поточні temp. Скасування HTTP-запиту не гарантує відсутності списання провайдера; відобразити unknown outcome, якщо відповідь не отримана.

**FR-047. Відновлення.** Jobs із незавершеним lease після перезапуску стають interrupted. Перевірити checkpoints і запропонувати resume тільки відсутніх/невалідних tasks. Невідомий paid outcome потребує явного рішення повторити; exactly-once billing не обіцяється.

**FR-048. Ключ.** Масковане введення API-key, перевірка підключення, заміна, видалення. Зберігати через OS encryption у main process; якщо недоступно — session-only режим. Не писати ключ у SQLite, localStorage, URL, argv, логи або manifest.

**FR-049. Бюджет.** Перед paid run показати моделі, обсяг, estimate та ліміт. Для невідомої ціни не показувати нуль: потрібен user ceiling і короткий pilot. Резервувати верхню оцінку наступного request атомарно; рахувати completed + reserved + unknown. При недостатньому залишку зупиняти нові запити.

**FR-050. Cache.** Ключ включає source hash, audio stream, extraction profile, STT model/provider/options або analysis profile/transcript revision/prompt/schema/model. Успіх кешувати; помилку не кешувати як готовий transcript. Ручні зміни зберігати окремо.

**FR-051. Помилки.** Стабільні error codes, український текст, дієва кнопка та request ID для діагностики. Логи не містять raw audio/key; транскрипти у debug dump лише за явним локальним експортом.

**FR-052. Cleanup.** Показати обсяг і перелік типів тимчасових даних перед очищенням. Видаляти лише всередині app-owned cache після resolved-path перевірки. Source originals і зовнішні exports не є cleanup targets.

## 5 Нефункціональні вимоги

**NFR-001. Простота.** Після одноразового налаштування типовий шлях до запуску аналізу ≤5 основних дій: проєкт, файл, категорії, запуск, підтвердження витрат. До локального ручного експорту API-key не потрібен.

**NFR-002. Відгук.** На reference machine дії вибору/фільтра/зміни меж p95≤200 мс без render; UI не блокується FFmpeg/API. Перший екран із ≤100 проєктами ≤3 с після готовності sidecar. Це ціль приймання, не виміряний результат.

**NFR-003. Масштаб.** Не читати весь відеофайл у RAM. Source 6 годин / 50 ГБ, до 2000 clips і 150000 words на проєкт. Список/транскрипція віртуалізовані, API pagination. Виміряти resident memory; ціль app+sidecar ≤2 ГБ поза FFmpeg, без вимоги GPU.

**NFR-004. Стабільність.** WAL + transactions + foreign keys; single writer coordination. Міграції versioned, backup перед міграцією. Конкурентні зміни clip захищені revision / optimistic concurrency, stale update →409.

**NFR-005. Безпека локального застосунку.** Renderer sandbox, context isolation, no Node integration; typed IPC allowlist; backend loopback-only із непередбачуваним session token. Транскрипція й output LLM — недовірені дані, не HTML і не команди.

**NFR-006. Доступність.** Клавіатурна навігація, видимий focus, текстові статуси, контраст основного тексту ≥4.5:1, масштаб Windows 100/125/150%, мінімальне підтримуване вікно 1100×720. Темна тема default, світла — P1.

**NFR-007. Відтворюваність.** Lock-файли, versioned prompts/schemas, модель і provider у run, tool versions у manifest. У CI не використовувати живий платний AI.

**NFR-008. Пакування.** Користувач отримує Windows пакет без ручного встановлення Python/Node. FFmpeg/FFprobe включені або встановлюються контрольованим first-run installer із перевіркою checksum/licensing. Обрати та перевірити один шлях у M0, default — bundle. Не називати unsigned build підписаним.

## 6 Приймання

Повний ручний і AI-assisted сценарії проходять на тестових записах. Готові кліпи починаються/закінчуються на заданих межах, звук синхронний, оригінали незмінні. Пошукові категорії працюють, порожній результат чесно відображається. Перезапуск не губить рішень і не повторює завершені платні задачі. Ключ не потрапляє в артефакти. Пройдено acceptance, UI, безпеку, VFR/offset/multi-track і 6-hour перевірки. Live provider та запуск packaged build на чистій Windows мають окремі звіти.

Початкова ціль AI-пілота: власник приймає ≥7 із top-10 на кожному з мінімум трьох придатних записів, які мають достатньо мовленнєво виражених моментів; середня ручна правка меж вимірюється. Це ціль калібрування, не гарантована властивість моделі. Для оцінки пропусків власник окремо позначає еталонні сцени; silent visual events рахуються окремо як обмеження цієї версії. Реліз не можна оголошувати таким, що виконав quality gate, без оцінки власником.
